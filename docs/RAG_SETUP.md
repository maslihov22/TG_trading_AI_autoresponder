# RAG Architecture Setup

## Обзор

Система теперь использует **RAG (Retrieval-Augmented Generation)** архитектуру для интеллектуальных ответов на основе базы знаний.

## Как это работает

### 1. **Knowledge Base (KB)**
- Все знания хранятся в папке `kb/` в формате JSONL
- Файлы:
  - `fd_behavior.jsonl` - поведение для First Deposit клиентов
  - `rd_behavior.jsonl` - поведение для Redeposit клиентов (добавьте его!)
  - `banks.jsonl` - информация о банках и реквизитах
  - `rules.jsonl` - общие правила и процедуры

### 2. **Embeddings + FAISS**
- При запуске система создаёт embeddings для каждого документа KB через Mistral AI API (`mistral-embed`)
- Embeddings индексируются в FAISS для быстрого поиска по векторному сходству
- Размерность: 1024 (mistral-embed)

### 3. **Retrieval Process**
Когда приходит сообщение от клиента:

1. **Контекст диалога** → Embedding
2. **Поиск** в FAISS индексе → top_k=3 релевантных документов
3. **Форматирование** найденных документов
4. **Промпт для ИИ** = короткий системный промпт + релевантные документы + диалог
5. **Генерация ответа** на основе контекста

### 4. **Системный промпт**
Теперь используется **короткий** промпт:

```
Eres X, un asesor de trading. Analiza el diálogo del cliente y usa la información relevante de la base de conocimiento proporcionada para responder adecuadamente.
```

Вся детальная информация (фазы, суммы, правила) подтягивается через retrieval.

## Преимущества RAG

✅ **Меньше токенов** - не нужно отправлять весь промпт каждый раз
✅ **Динамичность** - легко обновлять KB без изменения кода
✅ **Точность** - модель получает только релевантную информацию
✅ **Масштабируемость** - можно добавлять неограниченное количество документов

## Обновление Knowledge Base

### Добавление новых документов

1. Отредактируйте соответствующий JSONL файл в `kb/`
2. Добавьте новую строку в формате:
```json
{"id":"unique_id","title":"Заголовок","text":"Текст документа","source":"prompt_v1","last_updated":"2025-09-22","tags":["tag1","tag2"]}
```

3. Перезапустите систему - индекс пересоберётся автоматически

### Пересборка индекса во время работы (опционально)

В будущем можно добавить команду:
```python
kb_retriever.rebuild_index()
```

## Отладка

### Проверка retrieval
При обработке сообщения в логах будет:
```
🔍 Поиск релевантных документов в KB...
📚 Найдено 3 релевантных документов
```

### Проверка качества поиска
Документы с меньшим `score` (L2 distance) более релевантны.
